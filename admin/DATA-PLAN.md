**Test command**: read of `web-b-n-h-ng-cho-kh-ch/server/src/schema.ts` (full DDL mirror) and `actions.ts` lines 2285–2689 (existing adminOverview/adminListProducts/adminUpsertProduct/adminDeleteProduct/adminListOrders/adminUpdateOrderStatus/adminListDiscounts/adminUpsertDiscount/adminDeleteDiscount semantics to replicate 1:1); `artifact.status` on `web-b-n-h-ng-cho-kh-ch` returned `{shared:false, url:null}` — no public URL exists, so sidebar 'Xem web khách' cannot be a fabricated link and becomes an in-app note entry.

**Processing**: privileged handler opens `~/workspace/ts-spaces/web-b-n-h-ng-cho-kh-ch/app.db` (the exact file the shop's own ctx.db uses) with bun:sqlite, `busy_timeout=5000`, short transactions, parameterized SQL only. **Used by**: server actions → `ctx.executePrivileged(shopDb, ...)`
**Test command**: read `@hatch/space-sdk` server-contract.d.ts (definePrivilegedContracts / definePrivilegedHandlers / PrivilegedExecutor) and the working precedent `~/workspace/ts-spaces/social-desk/server/src/privileged.ts` (host handlers using node:child_process + fs, invoked synchronously from actions)

## Long-term data behavior
- **Refresh policy**: none — data is read live from the shared file on every action call; no cache, no sync job, no cron.
- **Growth**: unbounded reads capped like the shop's own admin (orders latest 500); products/variants returned in full (catalog is tens of rows).
- **Ordering**: products by id asc; variants by sort_order; orders by id desc (newest first).
- **Time semantics**: created_at stored as epoch-ms in the shared DB; rendered viewer-local (Asia/Ho_Chi_Minh) as dd/MM/yyyy HH:mm.

## Rejected approaches
- **Tried**: cross-artifact action invocation (`artifact.list_actions` on the shop slug)
  **Why rejected**: runtime refuses — `This task's data workspace belongs to web-qu-n-tr-b-n-xe-m-h-nh, not web-b-n-h-ng-cho-kh-ch`; and no SDK surface lets one artifact's actions call another's anyway.
- **Tried**: giving this artifact its own shop tables and syncing/mirroring
  **Why rejected**: user explicitly forbade a second database and any separate copy of products; a mirror can drift and would not be 'thấy ngay'.
- **Tried**: plain (non-privileged) server code opening the sibling file
  **Why rejected**: the action validator bans fs/process/host modules in the action bundle and directs host access to privileged.ts.

Imagery not needed: product thumbnails reuse the shop's existing image_key values already stored in the shared DB (rendered as the same keyed placeholder tiles the shop data carries); no new photos are sourced, and the ShopBase screenshots are layout reference only — none of their images, products, or branding enter the artifact.
